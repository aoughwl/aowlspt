# aowlspt_symbols.txt -- the ONLY place a by-name IL2CPP method becomes an RVA.
#
# `tools/il2cpp_symtab.py gen` resolves every line below offline, out of
# GameAssembly.dll plus the decrypted metadata, and emits
# abi/aowlspt_symtab.h and abi/aowlspt_symtab.nim.
#
# Nothing here is resolved at runtime. A runtime name lookup goes through a
# TOKEN-GATED il2cpp export -- one that takes a trailing argument the stock
# signature does not have -- and called the stock way it does not fail, it
# returns a plausible RANDOM value. Its failure mode is indistinguishable from
# success until something dereferences the answer, and by then the client is
# already dead with a log byte-identical to a healthy run. Resolving offline
# sidesteps the export ABI entirely: a byte-verified static RVA calls the
# compiled body directly. (Mechanism measured offline; see
# docs/IL2CPP_EXPORTS.md on feat-il2cpp-export-map.)
#
# FORMAT
#
#   IDENT = Ns.Type::Method/arity
#   IDENT = Ns.Type::Method/arity  shared-call why="at least 20 characters"
#
# `arity` may be `*`, which is honoured ONLY when the name has exactly one
# overload. The moment there are two, the symbol is REJECTED rather than
# guessed at -- `EFT.UI.Settings.SettingsScreen::Show` and
# `Scene::GetRootGameObjects` are both overloaded on this build.
#
# FOUR GATES, all applied at generation, all able to reject:
#   * the name must resolve to exactly ONE code address
#   * that address must be in the `il2cpp` PE section (generated METHOD code is
#     NOT in `.text`). This gate is about methods only -- the `il2cpp_*`
#     EXPORTS all live in `.text` and belong there.
#   * it must not be this build's universal empty-body stub -- found by owner
#     count AND opcode shape, not hardcoded. 9,614 method definitions resolve
#     to it, `TMP_Text::ForceMeshUpdate` among them.
#   * exactly ONE method definition must own it, unless `shared-call` is
#     written out with a reason.
#
# THE SHARED-CALL ESCAPE HATCH. The IL2CPP backend folds identical bodies, so
# unrelated methods share one address. CALLING a shared address is correct --
# it is the right code for the receiver you pass. DETOURING one is a write
# whose blast radius is every owner. So a shared symbol gets `AOWL_SYMC_<X>`
# and NO `AOWL_SYM_<X>`: a detour site cannot reach it by accident, it has to
# be typed on purpose, and this file has to carry the reason.
#
# Adding a symbol: find it first --
#   python tools\il2cpp_symtab.py find-method <GameAssembly.dll> \
#       .cache\global-metadata.dec.dat <substring>
# which prints the RVA, the section, the owner count, and a warning if it is
# the stub or shared. Then add a line here and rebuild.

# ------------------------------------------------- Bot AI (mods/sain) driving
# The five driving calls and the two sensors, resolved offline so that nothing
# in mods/sain ever asks the runtime for a name again. Every RVA and every
# signature below came from
#   python tools\il2cpp_resolve.py <gameasm> <metadec> type <idx>
# on 2026-08-26; the signatures are quoted in mods/sain/client/drivecalls.nim
# next to the call that stages the arguments for them.
#
# THE ONE THAT IS NOT HERE, and why. `BotMover::GoToPoint(Vector3, bool, float,
# bool, bool, bool, bool)` @0x1A2EE00 and `EFT.BotOwner::GoToPoint(Vector3,
# bool, float, bool, bool, bool, bool, bool)` @0x81CB40 are the real
# destination calls. They take 8 and 9 register slots INCLUDING `this`, and
# `AOWL_FAST_MAX_SLOTS` is 5 -- Win64 puts everything past the fourth argument
# on the STACK, which the shape dispatcher does not express and callrva.nim
# refuses rather than spills. Listing them here would produce a symbol that
# compiles and a call that can never be staged, so they are deliberately
# absent. See the BLOCKED note in mods/sain/README.md.
