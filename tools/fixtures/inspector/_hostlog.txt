# MEASURED HOST-LOG lines, NOT inspector batches.
#
# The leading `_` is load-bearing: `inspectfixtures.lint` requires every OTHER
# fixture file to carry a batch header, a batch trailer and at least one `>`
# echo, so that an echo-trap test is always constructible. These entries are
# single host-log lines and have none of those; they are exempt BY NAME, not by
# a special case someone can quietly widen.
#
# Every OUTPUT block is verbatim from a real capture on 2026-09-01/02. The
# `client  [t]warn` / `client  [t]ok  ` prefix is the form `aowl`'s stdout
# capture writes; the host's own aowlspt-host.log writes the same message with
# a `[t] warn   ` prefix instead. Consumers here match on the MESSAGE, not the
# prefix, so both forms feed the same parser -- but do not "normalise" these
# lines to one form, because then they would no longer be evidence of either.
#
# Entry format:  === ENTRY <id> / --- SOURCE / --- SHAPE / --- COMMAND /
#                --- OUTPUT <verbatim ...> / --- END
# COMMAND on a hostlog entry is the pseudo-command `hostlog <pattern>`: it is
# what the loader keys on, and it is NOT something the inspector accepts.
